package com.tripnest.backend.entity;
import jakarta.persistence.*;
import lombok.*;
import java.math.BigDecimal;
import java.time.LocalDateTime;
/**
 * Budget Entity represents the financial budget plan linked to a specific Trip.
 * It tracks the overall monetary ceiling and the allocated category targets.
 * 
 * Relationship: 1-to-1 with Trip (A trip has exactly one budget).
 */
@Entity
@Table(name = "budgets")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class Budget {
    // =========================================================================
    // PRIMARY KEY: Unique database ID for this budget record
    // =========================================================================
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    // =========================================================================
    // RELATIONSHIP: Every budget belongs to exactly ONE Trip.
    // 'unique = true' enforces at the database level that a trip cannot have 2 budgets.
    // 'fetch = FetchType.LAZY' avoids loading the whole Trip into memory unless needed.
    // =========================================================================
    @OneToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "trip_id", nullable = false, unique = true)
    private Trip trip;
    // =========================================================================
    // TOTAL BUDGET: Maximum planned expenditure for the vacation.
    // We use BigDecimal for financial precision (never float or double).
    // precision=12, scale=2 means up to 999,999,999.99 (up to 100 Crores with 2 decimals).
    // =========================================================================
    @Column(name = "total_budget", nullable = false, precision = 12, scale = 2)
    private BigDecimal totalBudget;
    // Currency code: Defaults to 'INR' (Indian Rupee), supports USD, EUR, etc.
    @Column(name = "currency", nullable = false, length = 10)
    @Builder.Default
    private String currency = "INR";
    // =========================================================================
    // CATEGORY BUDGET LIMITS (Allocations)
    // =========================================================================
    // Limit allocated for hotels, resorts, homestays
    @Column(name = "accommodation_limit", precision = 12, scale = 2)
    @Builder.Default
    private BigDecimal accommodationLimit = BigDecimal.ZERO;
    // Limit allocated for flights, trains, rental cars, cabs
    @Column(name = "transportation_limit", precision = 12, scale = 2)
    @Builder.Default
    private BigDecimal transportationLimit = BigDecimal.ZERO;
    // Limit allocated for restaurants, street food, cafes
    @Column(name = "food_limit", precision = 12, scale = 2)
    @Builder.Default
    private BigDecimal foodLimit = BigDecimal.ZERO;
    // Limit allocated for museum tickets, sports, guided tours
    @Column(name = "activities_limit", precision = 12, scale = 2)
    @Builder.Default
    private BigDecimal activitiesLimit = BigDecimal.ZERO;
    // Limit allocated for shopping, souvenirs, emergency cash
    @Column(name = "misc_limit", precision = 12, scale = 2)
    @Builder.Default
    private BigDecimal miscLimit = BigDecimal.ZERO;
    // =========================================================================
    // AUDIT TIMESTAMPS: Automatically tracks creation and update time
    // =========================================================================
    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;
    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;
    // Lifecycle hook: runs right before JPA inserts this row into PostgreSQL
    @PrePersist
    protected void onCreate() {
        this.createdAt = LocalDateTime.now();
        this.updatedAt = LocalDateTime.now();
        ensureNonNullLimits();
    }
    // Lifecycle hook: runs right before JPA updates this existing row in PostgreSQL
    @PreUpdate
    protected void onUpdate() {
        this.updatedAt = LocalDateTime.now();
        ensureNonNullLimits();
    }
    /**
     * Helper method to compute the sum of all 5 category limits.
     * Used by the service layer to check: (getTotalAllocated() <= totalBudget).
     */
    public BigDecimal getTotalAllocated() {
        ensureNonNullLimits();
        return accommodationLimit
                .add(transportationLimit)
                .add(foodLimit)
                .add(activitiesLimit)
                .add(miscLimit);
    }
    /**
     * Helper method to prevent NullPointerExceptions by converting nulls to ZERO.
     */
    private void ensureNonNullLimits() {
        if (this.accommodationLimit == null) this.accommodationLimit = BigDecimal.ZERO;
        if (this.transportationLimit == null) this.transportationLimit = BigDecimal.ZERO;
        if (this.foodLimit == null) this.foodLimit = BigDecimal.ZERO;
        if (this.activitiesLimit == null) this.activitiesLimit = BigDecimal.ZERO;
        if (this.miscLimit == null) this.miscLimit = BigDecimal.ZERO;
        if (this.totalBudget == null) this.totalBudget = BigDecimal.ZERO;
        if (this.currency == null) this.currency = "INR";
    }
}

Here is the deep-dive explanation for each of these three lines—why they exist, what SQL/Java they generate, and why they are essential for clean architecture.

1. @JoinColumn(name = "trip_id", nullable = false, unique = true)
In Java, an entity has a direct reference to another Java object:

java


private Trip trip;
However, PostgreSQL does not store Java objects—it only stores tables with numbers and text. @JoinColumn is the bridge between the Java object and the PostgreSQL table.

Let's break down all 3 parts of this annotation:

A. name = "trip_id"
This tells PostgreSQL: "Create a foreign key column named trip_id inside the budgets table."
In SQL, this maps to:
sql


budgets (
    id BIGINT PRIMARY KEY,
    trip_id BIGINT REFERENCES trips(id),  -- <--- generated by name = "trip_id"
    ...
)
B. nullable = false
Generates NOT NULL on the column in PostgreSQL:
sql


trip_id BIGINT NOT NULL
Why it matters: A budget cannot exist without a trip. You can never accidentally save an "orphan" budget floating around in the database with no trip attached.
C. unique = true ⭐ (The most important part!)
In a @ManyToOne relationship (like Activities 
→
→ Trip), many activities share the same trip_id = 5.
But for a Budget, Trip #5 must have at most ONE budget.
unique = true generates a UNIQUE constraint in PostgreSQL:
sql


CONSTRAINT uk_budget_trip UNIQUE (trip_id)
Why this is critical: If there is a race condition or a duplicate API click trying to create two budgets for the same trip, PostgreSQL immediately blocks it at the database level! It guarantees a strict 1-to-1 relationship.
2. @Builder (Lombok)
@Builder implements the classic Builder Design Pattern automatically, saving you from writing dozens of lines of boilerplate code.

The Problem it solves:
Without @Builder, if an entity has 8 fields, you have two bad options:

A messy constructor with 8 parameters:
java


// Hard to read, easy to accidentally swap food and transport!
Budget b = new Budget(null, trip, new BigDecimal("40000"), "INR", 
                      accLimit, transLimit, foodLimit, actLimit, miscLimit, now, now);
Ten lines of repetitive setters:
java


Budget b = new Budget();
b.setTrip(trip);
b.setTotalBudget(new BigDecimal("40000"));
b.setFoodLimit(new BigDecimal("8000"));
// ... repetitive and verbose
With @Builder:
You construct objects fluently, safely, and cleanly:

java


Budget budget = Budget.builder()
    .trip(trip)
    .totalBudget(new BigDecimal("40000"))
    .currency("INR")
    .foodLimit(new BigDecimal("8000"))
    .build();
Every field is explicitly named.
You only set the fields you care about; the rest get their safe defaults.
Interviewers love seeing the Builder pattern used in service layers.
3. @Builder.Default private BigDecimal activitiesLimit = BigDecimal.ZERO;
This solves a very famous Lombok trap that catches many junior developers!

The Trap:
In normal Java, when you write:

java


private BigDecimal activitiesLimit = BigDecimal.ZERO;
If you do new Budget(), activitiesLimit is 0.

BUT when you use Lombok's @Builder: Lombok creates a separate builder class in the background. By default, Lombok's builder ignores your inline default values (= BigDecimal.ZERO)!

If you do:

java


Budget b = Budget.builder()
    .totalBudget(new BigDecimal("40000"))
    .build();
Without @Builder.Default: Lombok leaves activitiesLimit as null!
Then later, when your code tries to calculate the total:
java


b.getActivitiesLimit().add(...) // 💥 NullPointerException! Application crashes!
What @Builder.Default does:
It explicitly tells Lombok:

"Hey Lombok, when someone builds a Budget using Budget.builder() and DOES NOT pass an activitiesLimit, initialize it to BigDecimal.ZERO instead of null!"

Thanks to @Builder.Default:

b.getActivitiesLimit() is always guaranteed to be BigDecimal.ZERO (0.00), never null.
No NullPointerExceptions anywhere in your financial calculations!

package com.tripnest.backend.repository;
import com.tripnest.backend.entity.Budget;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;
import java.util.Optional;
/**
 * BudgetRepository provides database access operations for the Budget entity.
 * By extending JpaRepository, Spring automatically generates CRUD methods 
 * (save, findById, delete, etc.) without writing any manual SQL.
 */
@Repository
public interface BudgetRepository extends JpaRepository<Budget, Long> {
    /**
     * Finds the unique budget linked to a specific trip ID.
     * 
     * Spring Data JPA derives the SQL query automatically from the method name:
     * -> SELECT * FROM budgets WHERE trip_id = ?
     * 
     * @param tripId the primary key of the Trip
     * @return Optional containing the Budget if configured, or Optional.empty() if not
     */
    Optional<Budget> findByTripId(Long tripId);
    /**
     * Checks whether a budget has already been created for a given trip.
     * Generates: SELECT COUNT(*) > 0 FROM budgets WHERE trip_id = ?
     * 
     * @param tripId the primary key of the Trip
     * @return true if a budget exists, false otherwise
     */
    boolean existsByTripId(Long tripId);
    /**
     * Deletes the budget associated with a given trip ID.
     * Generates: DELETE FROM budgets WHERE trip_id = ?
     * 
     * @param tripId the primary key of the Trip
     */
    void deleteByTripId(Long tripId);
}
🔍 Detailed Explanation of Key Concepts
1. extends JpaRepository<Budget, Long>
Budget: Tells Spring Data JPA which Entity this repository manages.
Long: Specifies the data type of the Primary Key (id field).
The Magic: Just by writing extends JpaRepository, Spring gives you over 20+ database methods for free without writing a single line of SQL:
budgetRepository.save(budget) 
→
→ does INSERT or UPDATE
budgetRepository.findById(id) 
→
→ does SELECT * WHERE id = ?
budgetRepository.delete(budget) 
→
→ does DELETE FROM budgets WHERE id = ?
2. How findByTripId(Long tripId) Works (Method Name Parsing)
Notice that we did NOT write any @Query("SELECT b FROM Budget...")!

Spring Data JPA parses the method name using reflection:
find...By 
→
→ Generate a SELECT query.
...TripId 
→
→ Look at the trip field inside Budget, and match its id (trip.id).
At runtime, Spring generates:
sql


SELECT * FROM budgets WHERE trip_id = ?;
3. Why return Optional<Budget> instead of just Budget?
In older Java, if a trip didn't have a budget yet, the method would return null.
If your service code then ran:
java


Budget b = budgetRepository.findByTripId(tripId);
b.getTotalBudget(); // 💥 Crash! NullPointerException if b was null!
With Optional<Budget>, Java forces you to handle the empty case gracefully:
java


Budget budget = budgetRepository.findByTripId(tripId)
    .orElseThrow(() -> new ResourceNotFoundException("No budget configured for trip: " + tripId));
This guarantees your backend never crashes with random NullPointerExceptions.
4. @Repository
Flags this interface as a Spring-managed Bean (Data Access Object).
It also enables Spring's automatic exception translation (it catches low-level database SQL errors like PSQLException and translates them into Spring's clean DataAccessException).

💡 Why do we need DTOs? Why not just expose Budget directly?
(This is a classic SDE-2 interview question!)

Security (Preventing Over-Posting / Mass Assignment Attacks):
If an API accepts a raw Budget entity, an attacker could send {"id": 1, "trip": {"id": 999}} and overwrite someone else's trip budget!
A DTO only accepts the fields the user is allowed to touch (totalBudget, category limits).
Input Validation:
Bean validation annotations (@NotNull, @Positive, @DecimalMin) live cleanly on the DTO.
Smart Computed Responses:
The database doesn't need to store redundant values like "unallocated money".
But the frontend wants to know: "How much money is left over to assign?"
BudgetResponse can calculate and return totalAllocated and unallocatedAmount automatically!

package com.tripnest.backend.dto.budget;
import jakarta.validation.constraints.DecimalMin;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Positive;
import lombok.Data;
import java.math.BigDecimal;
/**
 * BudgetRequest captures client input for creating or updating a trip budget.
 * Includes Bean Validation constraints to reject invalid financial payloads.
 */
@Data
public class BudgetRequest {
    // Total budget must be present and strictly greater than zero (e.g. >= 0.01)
    @NotNull(message = "Total budget is required")
    @Positive(message = "Total budget must be strictly greater than zero")
    private BigDecimal totalBudget;
    // Currency code (e.g. 'INR', 'USD'). Optional in request; defaults to INR in service if null.
    private String currency;
    // Category allocations: cannot be negative, but can be 0.00
    @DecimalMin(value = "0.0", inclusive = true, message = "Accommodation limit cannot be negative")
    private BigDecimal accommodationLimit;
    @DecimalMin(value = "0.0", inclusive = true, message = "Transportation limit cannot be negative")
    private BigDecimal transportationLimit;
    @DecimalMin(value = "0.0", inclusive = true, message = "Food limit cannot be negative")
    private BigDecimal foodLimit;
    @DecimalMin(value = "0.0", inclusive = true, message = "Activities limit cannot be negative")
    private BigDecimal activitiesLimit;
    @DecimalMin(value = "0.0", inclusive = true, message = "Miscellaneous limit cannot be negative")
    private BigDecimal miscLimit;
}

package com.tripnest.backend.service;
import com.tripnest.backend.dto.budget.BudgetRequest;
import com.tripnest.backend.dto.budget.BudgetResponse;
import com.tripnest.backend.entity.Budget;
import com.tripnest.backend.entity.Trip;
import com.tripnest.backend.entity.User;
import com.tripnest.backend.repository.BudgetRepository;
import com.tripnest.backend.repository.TripRepository;
import com.tripnest.backend.repository.UserRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.math.BigDecimal;
import java.util.Optional;
/**
 * BudgetService manages financial business logic for trip budgets.
 * 
 * Responsibilities:
 * 1. Validating that category limits do not exceed the total budget ceiling.
 * 2. Enforcing trip ownership (a user can only manage their own trip's budget).
 * 3. Handling create-or-update (upsert) logic cleanly.
 * 4. Computing unallocated funds for the response DTO.
 */
@Service
public class BudgetService {
    private final BudgetRepository budgetRepository;
    private final TripRepository tripRepository;
    private final UserRepository userRepository;
    // Constructor Injection (Spring best practice for immutability and testability)
    public BudgetService(BudgetRepository budgetRepository,
                         TripRepository tripRepository,
                         UserRepository userRepository) {
        this.budgetRepository = budgetRepository;
        this.tripRepository = tripRepository;
        this.userRepository = userRepository;
    }
    /**
     * Retrieves the budget for a specific trip.
     * 
     * @param tripId the trip ID
     * @param currentUserEmail the email of the authenticated user
     * @return BudgetResponse or null if no budget has been configured yet
     */
    @Transactional(readOnly = true)
    public BudgetResponse getBudgetByTripId(Long tripId, String currentUserEmail) {
        // 1. Verify trip exists and user has authorization to view it
        Trip trip = findTripAndVerifyAccess(tripId, currentUserEmail);
        // 2. Fetch budget from repository (returns empty Optional if not set)
        Optional<Budget> budgetOpt = budgetRepository.findByTripId(trip.getId());
        // 3. Map to response DTO or return null
        return budgetOpt.map(this::mapToResponse).orElse(null);
    }
    /**
     * Creates a new budget or updates an existing budget for a trip (Upsert).
     * 
     * @param tripId the trip ID
     * @param request the incoming budget targets
     * @param currentUserEmail the authenticated user's email
     * @return the saved and computed BudgetResponse
     */
    @Transactional
    public BudgetResponse createOrUpdateBudget(Long tripId, BudgetRequest request, String currentUserEmail) {
        // 1. Verify trip exists and belongs to the authenticated user
        Trip trip = findTripAndVerifyAccess(tripId, currentUserEmail);
        // 2. Safe null-handling for incoming category limits
        BigDecimal accLimit = safeZero(request.getAccommodationLimit());
        BigDecimal transLimit = safeZero(request.getTransportationLimit());
        BigDecimal foodLimit = safeZero(request.getFoodLimit());
        BigDecimal actLimit = safeZero(request.getActivitiesLimit());
        BigDecimal miscLimit = safeZero(request.getMiscLimit());
        // 3. Compute total allocated across all 5 categories
        BigDecimal totalAllocated = accLimit
                .add(transLimit)
                .add(foodLimit)
                .add(actLimit)
                .add(miscLimit);
        // 4. CRITICAL BUSINESS RULE: Category sum CANNOT exceed the total budget!
        if (totalAllocated.compareTo(request.getTotalBudget()) > 0) {
            throw new IllegalArgumentException(
                    "Total allocated category limits (" + totalAllocated + ") " +
                    "cannot exceed the total budget (" + request.getTotalBudget() + ")!"
            );
        }
        // 5. Check if a budget already exists for this trip (Update vs Create)
        Budget budget = budgetRepository.findByTripId(trip.getId())
                .orElseGet(() -> Budget.builder().trip(trip).build());
        // 6. Update budget fields
        budget.setTotalBudget(request.getTotalBudget());
        budget.setCurrency(request.getCurrency() != null && !request.getCurrency().isBlank() 
                ? request.getCurrency().toUpperCase() 
                : "INR");
        budget.setAccommodationLimit(accLimit);
        budget.setTransportationLimit(transLimit);
        budget.setFoodLimit(foodLimit);
        budget.setActivitiesLimit(actLimit);
        budget.setMiscLimit(miscLimit);
        // 7. Save to PostgreSQL database
        Budget savedBudget = budgetRepository.save(budget);
        // 8. Return enriched response DTO
        return mapToResponse(savedBudget);
    }
    /**
     * Deletes / resets the budget for a trip.
     * 
     * @param tripId the trip ID
     * @param currentUserEmail the authenticated user's email
     */
    @Transactional
    public void deleteBudget(Long tripId, String currentUserEmail) {
        Trip trip = findTripAndVerifyAccess(tripId, currentUserEmail);
        budgetRepository.deleteByTripId(trip.getId());
    }
    // =========================================================================
    // HELPER METHODS
    // =========================================================================
    /**
     * Validates that the trip exists and belongs to the authenticated user.
     */
    private Trip findTripAndVerifyAccess(Long tripId, String currentUserEmail) {
        Trip trip = tripRepository.findById(tripId)
                .orElseThrow(() -> new IllegalArgumentException("Trip not found with ID: " + tripId));
        User currentUser = userRepository.findByEmail(currentUserEmail)
                .orElseThrow(() -> new IllegalArgumentException("Authenticated user not found: " + currentUserEmail));
        // Ensure current user is the owner of this trip
        if (!trip.getOwner().getId().equals(currentUser.getId())) {
            throw new SecurityException("Unauthorized: You do not have permission to access or modify this trip's budget.");
        }
        return trip;
    }
    /**
     * Prevents NullPointerExceptions by treating null values as 0.00.
     */
    private BigDecimal safeZero(BigDecimal val) {
        return val != null ? val : BigDecimal.ZERO;
    }
    /**
     * Converts a database Budget entity into an enriched BudgetResponse DTO.
     */
    private BudgetResponse mapToResponse(Budget budget) {
        BigDecimal totalAllocated = budget.getTotalAllocated();
        BigDecimal unallocated = budget.getTotalBudget().subtract(totalAllocated);
        if (unallocated.compareTo(BigDecimal.ZERO) < 0) {
            unallocated = BigDecimal.ZERO;
        }
        return BudgetResponse.builder()
                .id(budget.getId())
                .tripId(budget.getTrip().getId())
                .totalBudget(budget.getTotalBudget())
                .currency(budget.getCurrency())
                .accommodationLimit(budget.getAccommodationLimit())
                .transportationLimit(budget.getTransportationLimit())
                .foodLimit(budget.getFoodLimit())
                .activitiesLimit(budget.getActivitiesLimit())
                .miscLimit(budget.getMiscLimit())
                .totalAllocated(totalAllocated)
                .unallocatedAmount(unallocated)
                .createdAt(budget.getCreatedAt())
                .updatedAt(budget.getUpdatedAt())
                .build();
    }
}
🔍 Key Architectural Highlights
1. @Transactional and @Transactional(readOnly = true)
In banking/finance systems, transactions ensure ACID compliance (Atomicity, Consistency, Isolation, Durability).
If an error occurs midway through saving a budget, @Transactional automatically rolls back everything so the database is never left in a corrupted half-saved state.
readOnly = true tells Hibernate to skip dirty-checking, boosting read performance!
2. The Business Validation Rule
java


if (totalAllocated.compareTo(request.getTotalBudget()) > 0) { ... }
Why use .compareTo() instead of == or >? In Java, BigDecimal objects cannot use comparison operators (>, <). a.compareTo(b) > 0 means 
a
>
b
a>b. If the sum of the 5 categories is ₹55,000 but the total budget is only ₹50,000, it throws an immediate IllegalArgumentException.
3. Safe Upsert (Create or Update in One Method)
java


Budget budget = budgetRepository.findByTripId(trip.getId())
        .orElseGet(() -> Budget.builder().trip(trip).build());
If a budget already exists for this trip, it updates it.
If it's the first time setting a budget, it creates a new one.
This is called an Upsert and makes the frontend API super simple (one endpoint handles both initial budgeting and editing).

Grabs the {tripId} from the URL path.

Logic Breakdown:
String userEmail = authentication.getName();:
Extracts the authenticated user's email from the JWT subject.
Security Best Practice: Notice we do not trust a userId passed in the request body! A malicious user could tamper with a body payload and pass someone else's userId. By extracting the identity directly from the cryptographically signed JWT token, we guarantee the user is who they claim to be.
budgetService.setOrUpdateBudget(...):
Hands the data over to the service layer to perform ownership verification, limit sum checks, and database save.
return ResponseEntity.ok(response);:
Returns an HTTP 200 OK status accompanied by the serialized BudgetResponse JSON.

write sql query to get, userid, user email, trip id, trip name, budget for each trip. budget id, budget amt
Here are the exact SQL queries for PostgreSQL to get this data.

Option 1: Only trips that HAVE a budget (INNER JOIN)
Use this if you only want to see trips where a budget has already been created:

sql


SELECT 
    u.id AS user_id,
    u.email AS user_email,
    t.id AS trip_id,
    t.title AS trip_name,
    b.id AS budget_id,
    b.total_budget AS budget_amt,
    b.currency
FROM users u
JOIN trips t ON t.user_id = u.id
JOIN budgets b ON b.trip_id = t.id
ORDER BY u.id, t.id;
Option 2: ALL trips, even if no budget is set yet (LEFT JOIN - Recommended ⭐)
Use this to see all your users and trips. If a trip doesn't have a budget yet, budget_id and budget_amt will clearly show as NULL (or 0.00):

sql


SELECT 
    u.id AS user_id,
    u.email AS user_email,
    t.id AS trip_id,
    t.title AS trip_name,
    b.id AS budget_id,
    COALESCE(b.total_budget, 0.00) AS budget_amt,
    COALESCE(b.currency, 'N/A') AS currency
FROM users u
JOIN trips t ON t.user_id = u.id
LEFT JOIN budgets b ON b.trip_id = t.id
ORDER BY u.id, t.id;
