While `ExpenseCategory.java` explicitly includes `SHOPPING`, `BudgetTab.jsx` only rendered `Shopping` in the actual spending audit with `limit={0}`, leaving it absent from Target Category Allocations and budget planning forms.
  * **Issue 2 (Payer Delegation):** Travelers frequently take turns paying group bills (e.g. Aln pays hotel, Ramanujan pays dinner). ### Proposal 15: Dual-Track Settlement Architecture (Way 1: Full-Squad Master Pool vs Way 2: Selective Expense-Wise Ledger) & Modal Companion Checkbox Allocation
* **Date:** 2026-09-30
* **User Suggestion:**
  > *"Section B (Way 1): Title: 🏁 Way 1: Pool Settlement Way: Trip-End Master Pool Settlement (Total Expenses ÷ 4 Members). Here all selected expense, say exp 1-8 here - total / 4. [All expenses where all mbrs present].*
  > *Section C (Way 2): Title: 🧾 Way 2: ExpenseWise Settlement Way: Itemized Receipt-by-Receipt Split (Granular Ledger). Here only selected expenses shud be there [whr only few were there, like only 2 or 3], say exp 9 btw 2 mbr [kim, aln], exp 10 btw 3 mbr [kim, aln, bell]. So, expense wise settlement btw mbrs.*
  > *Section 3 (summary of expenses): Displays the 10 categorized expense cards with companion shares beneath them. Finall summary of settlement.*
  > *Can we by default show all mbrs name in checkbox in logging exp time in card. And if only 3 mbrs involved then remv 4th mbr name from checkbox in logging exp time. Is it feasible.? Add this in Prosposedbyuser file too."*

* **Architectural Rationale & Feasibility Analysis:**
  * **Feasibility:** **100% Feasible, Highly Practical, and Architecturally Sound.**
  * **The Problem It Solves:** Real-world group trips comprise two kinds of expenses:
    1. **Common Pool Bills:** Expenses consumed by everyone (e.g. hotel villas, highway tolls, group rental van, shared dinners). These do not require tedious per-item micro-math—they just belong in a common pool divided equally by 4.
    2. **Subset / Selective Bills:** Expenses consumed by only a few companions (e.g. only 2 friends went paragliding, 3 friends had specialty drinks, or 1 friend bought personal groceries). These must be settled only among the participating sub-group.
  * **Modal Companion Checkboxes (Default: All Checked):**
    In the "Log New Expense" modal, displaying all squad members with checkboxes pre-selected by default is the most intuitive UX pattern:
    - If a bill is for the whole squad $\rightarrow$ Leave all checked (zero friction).
    - If a bill is for 2 or 3 members $\rightarrow$ Simply uncheck the absent member(s).
    - Upon saving the expense, the frontend immediately passes `userIds` to auto-split the bill among the checked members.

* **Planned Section Architecture in `SharedExpensesTab.jsx`:**
  1. **Section B — 🏁 Way 1: Pool Settlement Way (Trip-End Master Pool Settlement):**
     - Collects all expenses where all 4 squad members are participants (e.g. Expenses 1 to 8).
     - $\text{Total Pool Expenses} \div 4 = \text{Each Member's Fair Share}$.
     - **Table 1: Member Contribution:** Member | Total Paid Upfront | Fair Share | Net Position (+/−) | Status.
     - **Table 2: Logical Direct Settlement Plan ("Who Pays Whom"):**
       - Row 1: Bell pays ₹X to Aln — Status: Paid / Unsettled `[Mark Paid]`.
       - Row 2: Ramanujan pays ₹Y to Aln — Status: Paid / Unsettled `[Mark Paid]`.
       - Row 3: Kim pays ₹Z to Aln — Status: Paid / Unsettled `[Mark Paid]`.
  2. **Section C — 🧾 Way 2: ExpenseWise Settlement Way (Itemized Receipt-by-Receipt Split):**
     - Isolates subset expenses where only 2 or 3 members participated (e.g. Expense 9 between Aln & Kim; Expense 10 between Aln, Kim & Bell).
     - Displays specific expense-wise debt transfers between those particular companions.
  3. **Section 3 — 📑 Summary of Expenses & Final Reconciled Settlement:**
     - Displays the 10 categorized expense cards with category color themes, payer badges, and itemized companion shares.
     - Provides the final master reconciliation merging Way 1 + Way 2.

### Proposal 18: Permanent Chronological Expense Sequence Parity (Exp 1 ➔ Exp N ➔ Exp N+1) & Sort-Invariant Indexing

Storing `allExpenses` in state and mapping `expenseNumberMap = Map(expense.id -> chronologicalRank)` ensures that filtering by category retains each receipt's global trip-wide index.
